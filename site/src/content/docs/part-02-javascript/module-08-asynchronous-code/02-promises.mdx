**Goal:** By the end of this lesson you can use a promise's result with `then`, handle its failure with `catch`, and chain steps that depend on each other.

## Why it matters

`fetch`, the function the PayDeck app uses to talk to the API, returns a **promise**. So do most modern libraries, including the ones that store the sign-in token safely on the phone. Understanding promises is what makes the rest of this module, and the app's networking code, make sense.

## The idea

A **promise** is an object that stands for a value that is not ready yet. It is like the buzzer from the last lesson, but as a value you can store, pass around and attach code to.

A promise is always in one of three states:

| State | Meaning |
| --- | --- |
| **pending** | Still waiting |
| **fulfilled** | Finished, with a value (the coffee) |
| **rejected** | Failed, with an error (they ran out of milk) |

You attach code to it:

- `.then(callback)` runs when it is fulfilled, receiving the value.
- `.catch(callback)` runs when it is rejected, receiving the error.

## Worked example

Here is a pretend API call that takes half a second. (You will rarely write `new Promise` yourself, since libraries create them for you, but seeing one helps.)

```js
function fetchBalance(accountId) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (accountId === "a1") {
        resolve(124350);                            // fulfilled with a value
      } else {
        reject(new Error("Account not found"));     // rejected with an error
      }
    }, 500);
  });
}
```

Using it:

```js
const promise = fetchBalance("a1");
console.log(promise); // Promise { <pending> }

promise
  .then((cents) => console.log("Balance:", cents))
  .catch((error) => console.log("Failed:", error.message));

fetchBalance("zz")
  .then((cents) => console.log("Balance:", cents))
  .catch((error) => console.log("Failed:", error.message));
```

Output:

```
Promise { <pending> }
Balance: 124350
Failed: Account not found
```

- Printing the promise straight away shows `pending`: the value is not there yet.
- Half a second later, the first one is fulfilled and its `then` runs; the second is rejected and its `catch` runs.

### Chaining

`then` itself returns a new promise, resolved with whatever your callback returns. So steps that depend on each other read top to bottom, instead of nesting:

```js
fetchBalance("a1")
  .then((cents) => cents / 100)
  .then((dollars) => console.log(`$${dollars.toFixed(2)}`))
  .catch((error) => console.log("Failed:", error.message));
```

If any step fails, the chain skips straight to the `catch`. One `catch` at the end handles errors from every step.

## Try it

<Exercise title="Try it: a wait helper">
Write `wait(ms)`, which returns a promise that fulfils after `ms` milliseconds. Then use it to print `Processing…`, wait one second, and print `Approved`.

<Fragment slot="hint">Inside `new Promise((resolve) => ...)`, call `setTimeout` with `resolve` as the callback.</Fragment>
<Fragment slot="solution">

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

console.log("Processing…");
wait(1000).then(() => console.log("Approved"));
```

`resolve` is itself a function, so it can be the `setTimeout` callback directly. This little helper is useful for testing loading states in an app.

## Common mistakes

<Aside type="caution" title="UnhandledPromiseRejection">
A promise was rejected and nothing caught the error. Node stops the program with this message. Every promise chain needs a `catch` (or, in the next lesson, a `try`/`catch`).
</Aside>

<Aside type="caution" title={"[object Promise] or Promise { <pending> }"}>
You used the promise as if it were the value. The value only exists inside `then` (or after `await`).
</Aside>

## Recap

- A **promise** stands for a value that arrives later. It is pending, then fulfilled or rejected.
- `.then(fn)` gets the value; `.catch(fn)` gets the error.
- `then` returns a promise, so steps chain top to bottom, and one `catch` covers them all.
