**Goal:** By the end of this lesson you can write code that does different things depending on a condition.

## Why it matters

When someone pays with a PayDeck card, the server decides: is the card frozen? Over its limit? Is there enough money? Each answer leads somewhere different: approve, or decline with a reason. Every decision like that in every app is built from `if` and `else`.

## The idea

```js
if (condition) {
  // runs only when the condition is true
} else {
  // runs only when it is false
}
```

- The **condition** goes in round brackets. It is anything that is `true` or `false`, such as `amountCents > balanceCents` ("is the amount greater than the balance?").
- The code to run goes in curly braces `{ }`, called a **block**. It is indented by two spaces so you can see what belongs to what.
- `else` is optional.

For more than two choices, chain `else if`. JavaScript checks each condition from the top and runs the **first** block whose condition is true, then skips the rest:

```js
if (first) {
  // ...
} else if (second) {
  // ...
} else {
  // none of the above
}
```

The comparison operators you need for now: `>` greater than, `<` less than, `>=` greater than or equal, `<=` less than or equal, `===` equal, `!==` not equal. The next lesson covers them in depth.

## Worked example: should this payment go through?

Create `pay.js`:

```js
const balanceCents = 5000;
const isFrozen = false;
const amountCents = 1200;

if (isFrozen) {
  console.log("Declined: this card is frozen.");
} else if (amountCents > balanceCents) {
  console.log("Declined: not enough money.");
} else {
  console.log("Approved.");
}
```

`node pay.js` prints `Approved.` Now change the inputs and run it again:

- `isFrozen = true` → `Declined: this card is frozen.`
- `amountCents = 9000` → `Declined: not enough money.`
- Both → `Declined: this card is frozen.` Only the first matching branch runs, so the **order** of the checks is part of the logic. PayDeck's real API checks in this order: frozen, cancelled, over the limit, then not enough money.

Notice `if (isFrozen)`: a boolean is already true or false, so you do not need `if (isFrozen === true)`.

## Common mistakes

<Aside type="caution" title="if (amountCents = 0)">
A single `=` **puts** 0 into the variable instead of comparing, and the condition is then 0, which counts as false. To compare, always use `===`.
</Aside>

<Aside type="caution" title="Unexpected token 'else'">
Usually a missing or extra curly brace before the `else`. Each `{` needs a matching `}`. Turn on **Format Document** (Shift + Option + F) in VS Code: when the indentation looks wrong, a brace is out of place.
</Aside>

## Recap

- `if (condition) { ... }` runs a block only when the condition is true; `else` runs when it is false.
- `else if` adds more choices; only the **first** matching block runs, so order matters.
- A boolean can be the whole condition: `if (isFrozen)`.
