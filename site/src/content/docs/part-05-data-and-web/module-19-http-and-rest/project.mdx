Real developers often meet an API they have never seen, with nothing but its documentation. In this project you explore one on the internet with the tools from this module, and write down what you learn as a `.http` file that someone else could use.

The API is **JSONPlaceholder**, a free service made for practising. It pretends to be a small blogging site with users, posts, comments and to-dos. It accepts `POST`, `PATCH` and `DELETE` and answers as if they worked, but it does not really save anything, so you cannot break it.

## The tasks

Make a file `~/Projects/course/http/jsonplaceholder.http` with `@baseUrl = https://jsonplaceholder.typicode.com` at the top, and answer each question with a request in the file. Use `curl` and `jq` too when it is quicker for counting.

1. **Read the documentation.** Open [jsonplaceholder.typicode.com](https://jsonplaceholder.typicode.com) in your browser and find the list of resources and routes. Which six resources does it have?
2. **Collections.** How many users are there? How many posts?
3. **One item.** What is the name and email address of user 1?
4. **Filtering.** Using a query, list only the posts written by user 1. How many are there?
5. **Nested resources.** Using a path rather than a query, list the comments on post 1. How many are there?
6. **Create.** `POST` a new post for user 1. What status and `id` come back? Then `GET` that `id`. What happens, and why?
7. **Change and delete.** `PATCH` post 1's title, then `DELETE` post 1. What status does each return?
8. **Errors.** What does the API return for a post that does not exist?
9. **Types.** Write a TypeScript interface and a Java record for a user, with just `id`, `name`, `username` and `email`.

Counting with curl and jq:

```sh
curl -s https://jsonplaceholder.typicode.com/users | jq length              # 10
curl -s https://jsonplaceholder.typicode.com/posts | jq length              # 100
curl -s 'https://jsonplaceholder.typicode.com/posts?userId=1' | jq length   # 10
curl -s https://jsonplaceholder.typicode.com/posts/1/comments | jq length   # 5
```

Task 9:

```ts
interface User {
  id: number;
  name: string;
  username: string;
  email: string;
}
```

```java
record User(long id, String name, String username, String email) {}
```

What to notice:

- Two ways to ask for "the comments on post 1": the nested path `/posts/1/comments` and the query `/comments?postId=1`. Both are common in REST APIs.
- The `DELETE` answered `200 OK` with `{}` rather than `204 No Content`. Both are acceptable; APIs differ, which is why you read the responses rather than assume.
- The 404 has an empty body with no explanation. Compare the practice API's `{"error": "No card with id 9"}`. In Part 6 you will make sure PayDeck's errors always explain themselves.
- A user has more fields than the four you described (an address, a phone number, a company). Your types only need the fields your app uses; extra JSON fields are ignored.

<Aside type="note" title="Being a good API citizen">
Public APIs are shared by everyone. Send requests by hand or a few at a time, never in a fast loop. Many APIs limit how many requests each person may send, and answer `429 Too Many Requests` when you go over.
</Aside>
