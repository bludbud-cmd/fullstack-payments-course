Push has more moving parts than anything else in PayDeck: a Firebase project, a key file, a permission prompt, a token, two switches, and an API that decides who hears what. When a notification does not arrive, which part is to blame? This project adds the tool every real app has for that question, a **test notification**, and then uses it and the API's log to check every kind of event, end to end.

## The tasks

1. **The endpoint.** `POST /api/me/notifications/test` sends "PayDeck: Notifications work on this phone." to every phone of the signed-in person, whatever their switches say (they asked for it). It answers how many phones it reached, as `{"sent": 1}`, and deletes any phone Firebase says is gone.
2. **A test** in `PushNotificationTest`: two phones, one of them gone. The first call reaches one phone and forgets the other; the second call does not try the gone phone again.
3. **The button.** Under the switches on **You**: **Send me a test notification**, and below it "Sent to 1 phone." or, for zero, a sentence that says what to do.
4. **The full check.** With the API's log open, make every kind of event happen and check who is notified (the table in the solution).
5. Commit.

### The endpoint

In `DeviceController`, add `PushSender push` to the fields and constructor, a record:

```java
    public record TestNotificationResult(int sent) {
    }
```

and the endpoint:

```java
    /** "Does this work?": one notification to each of your phones, whatever your settings say. */
    @PostMapping("/api/me/notifications/test")
    @Transactional
    public TestNotificationResult sendTest(CurrentUser user) {
        int sent = 0;
        for (Device device : devices.findByUserId(user.id())) {
            PushSender.Result result = push.send(device.getToken(), "PayDeck", "Notifications work on this phone.");
            if (result == PushSender.Result.SENT) {
                sent++;
            } else if (result == PushSender.Result.TOKEN_GONE) {
                devices.delete(device);
            }
        }
        return new TestNotificationResult(sent);
    }
```

Only `SENT` counts. A phone whose token is gone is deleted, and a failure (Firebase down, wrong key) is simply not counted, so "Sent to 0 phones" with a phone registered points at the server's setup, and the API's log says what went wrong (lesson 34.4).

### The test

In `PushNotificationTest`:

```java
    @Test
    void aTestNotificationGoesToEveryPhoneThatStillWorks() throws Exception {
        TestUser asha = register("Asha");
        String phone = "phone-" + UUID.randomUUID();
        String oldPhone = "old-" + UUID.randomUUID();
        when(push.send(eq(phone), anyString(), anyString())).thenReturn(PushSender.Result.SENT);
        when(push.send(eq(oldPhone), anyString(), anyString())).thenReturn(PushSender.Result.TOKEN_GONE);
        registerPhone(asha, phone);
        registerPhone(asha, oldPhone);

        mvc.perform(post("/api/me/notifications/test").with(as(asha)))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.sent").value(1));
        mvc.perform(post("/api/me/notifications/test").with(as(asha)))
                .andExpect(jsonPath("$.sent").value(1));

        verify(push, Mockito.times(2)).send(eq(phone), eq("PayDeck"), eq("Notifications work on this phone."));
        verify(push, Mockito.times(1)).send(eq(oldPhone), anyString(), anyString());
    }
```

### The button

`src/api/paydeck.ts`:

```ts
/** One notification to each of your phones. Answers how many it reached. */
export const sendTestNotification = () =>
  request<{ sent: number }>('/api/me/notifications/test', { method: 'POST' });
```

`src/api/hooks.ts`:

```ts
export function useSendTestNotification() {
  return useMutation({ mutationFn: api.sendTestNotification });
}
```

In `NotificationSwitches`, `const test = useSendTestNotification();` next to `save`, and below the error text:

```tsx
      <Button title="Send me a test notification" variant="secondary" onPress={() => test.mutate()} />
      {test.data !== undefined && (
        <Text style={styles.muted}>
          {test.data.sent === 0

      )}
      {test.error && <Text style={styles.error}>{test.error.message}</Text>}
```

dev.paydeck.api.push.PushConfig          : Push (not sent, Firebase is not set up): Refund from Bakery: $4.50 is back in your wallet

Telling Eve is right: she made the payment. But "back in **your** wallet" is only true for Asha. Eve has no wallet on that account; the money went back to Asha's. ## What to notice

- **Make the invisible testable.** Push fails silently by design. A button that reports "Sent to 1 phone" splits the problem in two: the phone and Firebase, or the server.
- **The server decides, every time.** Who hears what is decided in one method, `LiveUpdates.deliver`, from the person's settings. The phone only shows what it is sent.
- **Optional by design.** Without Firebase, without permission, or on the Mac, PayDeck loses nothing but the buzz: the live feed and the Activity list still tell the whole story.
