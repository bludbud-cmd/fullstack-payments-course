**Goal:** By the end of this lesson you can build a signed release of PayDeck for Android that talks to your deployed API, and you know what to keep safe so you can release the next version too.

<Aside type="note" title="What the course ran">
The key commands (`keytool`) and the code changes in this lesson were run and checked by the course. The Android build itself (`./gradlew bundleRelease`) needs Android Studio's SDK, which the course's own build machine does not have, so its output below is described, not pasted. The course's GitHub Actions build the same Android project on every change (lesson 36.6).
</Aside>

## Why it matters

Everything so far ran as a **debug** build: the app on the emulator asks Metro, on your Mac, for its JavaScript every time it starts, and it talks to `10.0.2.2:8080`. Nobody else can use that. A **release** build carries its own JavaScript, talks to the real API over HTTPS, and is **signed** with your key, which is how Android and Google Play know that version 2 comes from the same person as version 1.

## The idea

### Debug and release

| | Debug | Release |
|---|---|---|
| JavaScript | fetched from Metro on your Mac | bundled inside the app, made smaller |
| `__DEV__` | `true` | `false` |
| Red error screens, reload | yes | no: an error closes the app |
| `http://` to other computers | allowed | refused, only `https://` |
| Signed with | a shared debug key | **your** upload key |

### Signing and the upload key

Android refuses to install an app that is not signed, and refuses to update an app with one signed by a different key. Google Play adds a layer: you sign with your **upload key**, and Play re-signs what it delivers to phones with its own **app signing key** (Play App Signing). If you lose the upload key, Google can reset it after checking who you are; if someone steals it, they can upload a version of your app. So: one key, backed up, never in Git.

### Two kinds of file

- An **`.aab`** (Android App Bundle) is what you upload to Google Play. Play makes the right `.apk` for each phone from it.
- An **`.apk`** installs directly on a phone or emulator, for testing or sharing with a friend.

## Worked example

### Point the app at the server

`src/config.ts` decided the API's address by platform only. Now it also asks `__DEV__`:

```ts
import { Platform } from 'react-native';

/**
 * Where your deployed API lives (Module 36). Change it to your own address
 * before building a release. It must be https://: release builds refuse
 * plain http:// to other computers.
 */
const PRODUCTION_API_URL = 'https://api.example.com';

/**
 * Where the PayDeck API runs. While you develop (__DEV__ is true) it is your
 * Mac: localhost on the Mac itself, and the special address 10.0.2.2 from the
 * Android emulator, a separate (virtual) device. Release builds use the
 * deployed API.
 */
export const API_BASE_URL = __DEV__
  ? Platform.OS === 'android'
    ? 'http://10.0.2.2:8080'
    : 'http://localhost:8080'
  : PRODUCTION_API_URL;

/**
 * Where the browser goes to sign in with Google. Google accepts plain http://
 * only for localhost, so while you develop this is localhost on Android too,
 * where `adb reverse tcp:8080 tcp:8080` forwards it to the Mac.
 */
export const SIGN_IN_BASE_URL = __DEV__ ? 'http://localhost:8080' : PRODUCTION_API_URL;
```

Put your own `https://` address (lesson 36.2) in `PRODUCTION_API_URL`. The live feed follows automatically: `LiveUpdates` turns `https://` into `wss://` with the same `replace(/^http/, 'ws')` as before. In tests `__DEV__` is `true`, so `npm test` still passes all 20 tests.

### Make the upload key

`keytool` comes with Java. In your home folder (not the project):

```sh
cd ~
keytool -genkeypair -v -storetype PKCS12 -keystore paydeck-upload.keystore \
  -alias paydeck-upload -keyalg RSA -keysize 2048 -validity 10000
```

It asks for a password (twice) and your name and organisation, then:

```
Generating 2048-bit RSA key pair and self-signed certificate (SHA384withRSA) with a validity of 10,000 days
	for: CN=Asha Example, O=PayDeck
[Storing paydeck-upload.keystore]
```

- A **keystore** is a password-protected file of keys. This one holds one key, called `paydeck-upload` (the **alias**).
- `-validity 10000` is about 27 years. Google Play requires the key to last well beyond 2033.

Check it:

```sh
keytool -list -keystore paydeck-upload.keystore
```

```
Your keystore contains 1 entry

paydeck-upload, Nov 4, 2026, PrivateKeyEntry,
Certificate fingerprint (SHA-256): 40:2B:0C:EE:32:1D:88:CD:C7:7D:10:9D:7E:11:BC:B9:38:7D:80:30:56:85:90:6B:99:A0:7B:5D:59:9F:47:20
```

Your fingerprint will be different: it is made from your new key. Now put a copy of the file and its password in your password manager. Without them you cannot sign the next version.

### Tell Gradle where it is

The password must not go in the project. Gradle also reads `~/.gradle/gradle.properties` in your home folder. Add (with your password):

```properties
PAYDECK_UPLOAD_STORE_FILE=/Users/asha/paydeck-upload.keystore
PAYDECK_UPLOAD_STORE_PASSWORD=the-password-you-chose
PAYDECK_UPLOAD_KEY_ALIAS=paydeck-upload
PAYDECK_UPLOAD_KEY_PASSWORD=the-password-you-chose
```

(With a PKCS12 keystore, the key's password is the same as the store's.)

In `android/app/build.gradle`, the template signs release builds with the debug key. Add a `release` signing config that reads those four names, and use it when it exists:

```groovy
    signingConfigs {
        debug {
            storeFile file('debug.keystore')
            storePassword 'android'
            keyAlias 'androiddebugkey'
            keyPassword 'android'
        }
        // Your own upload key for Google Play (Module 36). The file and its
        // passwords come from ~/.gradle/gradle.properties or the environment
        // (ORG_GRADLE_PROJECT_PAYDECK_UPLOAD_STORE_FILE and so on), never git.
        if (findProperty('PAYDECK_UPLOAD_STORE_FILE')) {
            release {
                storeFile file(findProperty('PAYDECK_UPLOAD_STORE_FILE'))
                storePassword findProperty('PAYDECK_UPLOAD_STORE_PASSWORD')
                keyAlias findProperty('PAYDECK_UPLOAD_KEY_ALIAS')
                keyPassword findProperty('PAYDECK_UPLOAD_KEY_PASSWORD')
            }
        }
    }
    buildTypes {
        debug {
            signingConfig signingConfigs.debug
        }
        release {
            // Signed with your upload key when you have set one up. Otherwise
            // with the debug key: fine for trying a release build on your own
            // phone, but Google Play will not accept it.
            signingConfig signingConfigs.findByName('release') ?: signingConfigs.debug
            minifyEnabled enableProguardInReleaseBuilds
            proguardFiles getDefaultProguardFile("proguard-android.txt"), "proguard-rules.pro"
        }
    }
```

- `findProperty('...')` reads a Gradle property, from `gradle.properties` or from an environment variable called `ORG_GRADLE_PROJECT_` plus the name. Lesson 36.6 uses the second way on GitHub's machines.
- `if (findProperty(...))` means the project still builds on a computer without your key (a teammate's, or CI before the secrets are set), signed with the debug key.
- `?:` is Groovy's "or else": the release config if there is one, the debug one otherwise.

### The version

Above, in `defaultConfig`:

```groovy
        versionCode 1
        versionName "1.0"
```

- `versionCode` is a whole number that Google Play uses to know which build is newer. Every upload must have a higher one: 1, 2, 3...
- `versionName` is what people see in the store, "1.0", "1.1". It can be anything.

### Build it

```sh
cd android
./gradlew bundleRelease
```

The first release build takes several minutes: it bundles the JavaScript, compiles for every phone processor, and signs. The file it makes is `android/app/build/outputs/bundle/release/app-release.aab`. For an `.apk` to try on the emulator:

```sh
./gradlew assembleRelease
adb install app/build/outputs/apk/release/app-release.apk
```

Open PayDeck on the emulator. There is no Metro window and no reload menu, and it signs in against your server. If you set up push in Module 34, the emulator's token is now registered with the server's database, not your Mac's.

### Google Play

<Aside type="caution" title="Not done by the course">
Publishing needs a Google Play developer account (a one-time fee), which the course does not require. The outline: create the app in the Play Console, fill in its store listing and the data-safety form (PayDeck stores emails and payment history), upload `app-release.aab` to the **Internal testing** track, and add your testers' Google accounts. They get a link to install it from the Play Store. Play's own guides have the current screens.
</Aside>

## Common mistakes

<Aside type="caution" title="Committing the keystore or its password">
Anyone with both can sign apps as you. Keep the file in your home folder and a password manager. `.gitignore` in the React Native template already ignores `*.keystore` except the debug one; do not add exceptions.
</Aside>

<Aside type="caution" title="A release that still talks to 10.0.2.2">
That address only means "my Mac" inside the emulator. A release on a real phone needs the server's `https://` address in `config.ts`.
</Aside>

<Aside type="caution" title="Forgetting to raise versionCode">
Google Play refuses the upload ("Version code 1 has already been used"). Raise it for every build you upload.
</Aside>

## Recap

- Release builds bundle the JavaScript, set `__DEV__` to `false`, need `https://`, and are signed with your key.
- `config.ts` picks the deployed API when `__DEV__` is `false`.
- Make one upload key with `keytool`, keep it and its password out of Git and backed up; Gradle reads them from `~/.gradle/gradle.properties`.
- `versionCode` goes up for every upload; `versionName` is for people.
- `./gradlew bundleRelease` makes the `.aab` for Google Play, `assembleRelease` an `.apk` to install directly.
