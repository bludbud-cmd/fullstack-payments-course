The Activity screen from the Module 33 mini-project is the hardest screen to check by hand: its status line depends on a WebSocket, and its highlight depends on what arrives while you watch. This project tests it in Jest, lets one of the tests point out a weakness in the screen, and prepares the app's tests for Module 36, where GitHub runs them on every push.

## The tasks

1. **Activity tests.** In `__tests__/ActivityScreen.test.tsx`, test that the screen says "No transactions yet." for an empty list, that it shows the live status ("Reconnecting…" when `useLiveStatus` says `reconnecting`), and that a transaction that arrives while the screen is open is marked as new.
2. **A label, not just a colour.** New rows are only shown by a blue background. A screen reader cannot see colour, and some people cannot tell it apart. Write the test first: a new row has a visible **New** label above it. Watch it fail, then make it pass.
3. **Live tests apart.** Move `push.test.ts` (lesson 34.2), which needs the API and Docker, into `__tests__/live/`. Make `npm test` skip that folder, and add `npm run test:live` to run it.
4. Run `npm test`, and commit.

### The tests

`__tests__/ActivityScreen.test.tsx`:

```tsx
import { act, screen } from '@testing-library/react-native';
import * as authApi from '../src/api/auth';
import * as api from '../src/api/paydeck';
import { useLiveStatus } from '../src/live/LiveUpdates';
import { ActivityScreen } from '../src/screens/ActivityScreen';
import type { Activity } from '../src/types';
import { asha, ashasAccount } from '../testing/data';
import { renderScreen } from '../testing/renderScreen';

jest.mock('../src/api/auth');
jest.mock('../src/api/paydeck');
// The real LiveUpdates opens a WebSocket. Here, each test says what the status is.
jest.mock('../src/live/LiveUpdates', () => ({ useLiveStatus: jest.fn() }));
const mocked = jest.mocked(api);

const coffee: Activity = {
  transactionId: 't-1',
  type: 'CARD_PAYMENT',
  description: 'Corner Café',
  amountCents: -1_250,
  createdAt: '2026-11-04T09:00:00Z',
};
const bread: Activity = { ...coffee, transactionId: 't-2', description: 'Bakery', amountCents: -450 };

beforeEach(() => {
  jest.mocked(authApi.getMe).mockResolvedValue(asha);
  mocked.getAccount.mockResolvedValue(ashasAccount);
  jest.mocked(useLiveStatus).mockReturnValue('live');
});

describe('ActivityScreen', () => {
  it('says when there is nothing yet', async () => {
    mocked.getActivity.mockResolvedValue([]);
    await renderScreen(<ActivityScreen />);

    expect(await screen.findByText('No transactions yet.')).toBeOnTheScreen();
  });

  it('says whether updates are live', async () => {
    mocked.getActivity.mockResolvedValue([coffee]);
    jest.mocked(useLiveStatus).mockReturnValue('reconnecting');
    await renderScreen(<ActivityScreen />);

    expect(await screen.findByText('Reconnecting…')).toBeOnTheScreen();
  });

  it('marks what arrived while watching as new', async () => {
    mocked.getActivity.mockResolvedValue([coffee]);
    const { queryClient } = await renderScreen(<ActivityScreen />);
    await screen.findByText('Corner Café');
    expect(screen.queryByText('New')).not.toBeOnTheScreen();

    // What the live feed does when Eve pays: the list is fetched again, with one more row.
    mocked.getActivity.mockResolvedValue([bread, coffee]);
    await act(() => queryClient.invalidateQueries());

    expect(await screen.findByText('Bakery')).toBeOnTheScreen();
    // Top to bottom: the label, the new row, the old row.
    expect(screen.getAllByText(/^(New|Bakery|Corner Café)$/).map((text) => text.props.children)).toEqual([
      'New',
      'Bakery',
      'Corner Café',
    ]);
  });
});
```

- `jest.mock` with a **factory** (the second argument) replaces the module with exactly what it returns. The real `LiveUpdates` is never loaded, so no WebSocket.
- `act(...)` tells React a change is coming from outside a `fireEvent`, and waits for the screen to settle.
- The last check reads every matching text **in order**, so it proves the label is above the new row, not somewhere else.

Before the screen has a label:

```
  ● ActivityScreen › marks what arrived while watching as new

    expect(received).toEqual(expected) // deep equality

    - Expected  - 1
    + Received  + 0

      Array [
    -   "New",
        "Bakery",
        "Corner Café",
      ]
```

### The label

In `ActivityScreen.tsx`, the rows become:

```tsx
      {activity.data.map((item) => {
        const fresh = !seen.current?.has(item.transactionId);
        return (
          <View key={item.transactionId} style={fresh && styles.fresh}>
            {/* Colour alone is invisible to a screen reader, and to some eyes. */}
            {fresh && <Text style={styles.newLabel}>New</Text>}
            <ActivityRow item={item} currency={currency} />
          </View>
        );
      })}
```

and one more style:

```ts
  newLabel: { color: '#3c4fe0', fontWeight: '700', fontSize: 12 },
```

(`paddingTop: 6` on `fresh` gives the label a little room.) Now the test passes, and a screen reader reads "New" before the new row.

### Live tests apart

```sh
mkdir -p __tests__/live
git mv __tests__/push.test.ts __tests__/live/push.test.ts
```

In the moved file, imports go one folder further up: `'../src/...'` becomes `'../../src/...'`. Then `jest.config.js`:

```js
module.exports = {
  preset: 'react-native',
  setupFiles: ['<rootDir>/jest.setup.js'],
  // Forget what every jest.fn() was called with before each test.
  clearMocks: true,
  // Tests in __tests__/live need the API running. `npm test` skips them; `npm run test:live` runs them.
  testPathIgnorePatterns: ['/node_modules/', '<rootDir>/__tests__/live/'],
};
```

and in `package.json`'s `scripts`:

```json
    "test": "jest",
    "test:live": "jest --testPathIgnorePatterns /node_modules/ --runInBand __tests__/live"
```

`--testPathIgnorePatterns` on the command line replaces the one in the config, so the live folder is not ignored; `__tests__/live` then picks only those tests; `--runInBand` runs them one at a time, because they share one API and one database.

## What to notice

- **Mock at the edges.** The API modules and the WebSocket are mocked; everything between them and the screen (hooks, cache, components) is the real code.
- **Tests can improve the product.** Writing "a new row is marked" made it obvious that colour alone does not mark it for everyone.
- **Fast by default.** `npm test` needs nothing running, which is what lets Module 36 run it on GitHub's computers for every push.
