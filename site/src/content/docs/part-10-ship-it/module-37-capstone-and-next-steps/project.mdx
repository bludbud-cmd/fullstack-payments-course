This is the last project of the course. There is no new code to learn: the job is to finish. A finished project has a version number, a page that explains it, something people can download, and an author who can talk about it.

## The tasks

1. **Polish pass.** Lesson 37.1's checklist on every screen. Fix what a customer would notice, each with a test. `npm test` and `./mvnw verify` green.
2. **READMEs.** Both projects, in the shape of lesson 37.2, with screenshots in `docs/` and every number true.
3. **Version 1.0.** Set the versions (Android `versionCode 1`, `versionName "1.0"`; Mac `1.0` and `1`), tag both repositories `v1.0.0`, and create a **GitHub release** for each, with the Android `.apk` and the zipped Mac app attached to the app's release.
4. **A demo.** A screen recording of at most ninety seconds: sign in, pay on one device, see it arrive live on the other, freeze the card, see the next payment declined with the reason.
5. **A look back.** A page of your own notes: what was hardest, what you are proudest of, what you would do differently, and your next project (lesson 37.4).

### Version 1.0

Lesson 36.4 and 36.5 already set Android to `1` / `"1.0"` and the Mac to `1.0` / `1`. Tag each repository, after the last commit:

```sh
git tag v1.0.0
git push origin v1.0.0
```

A **tag** is a name for one commit that never moves (unlike a branch). `v1.0.0` follows **semantic versioning**: the first number changes when something stops working the old way, the second when something is added, the third for fixes. Your next bug fix is `v1.0.1`.

On GitHub, **Releases → Draft a new release**, choose the tag, title it "PayDeck 1.0", and write three lines on what it does (the README's first paragraph will do). For the app, drag in `app-release.apk` (lesson 36.4) and `PayDeck-macOS.zip` (lesson 36.5), and add one line for Mac users: "Unsigned: the first time, open it from System Settings → Privacy & Security → Open Anyway." If you set up lesson 36.6's release workflow, the tag built them for you: download them from that run's artifacts.

Do not attach the `.aab`: it is for Google Play, not for people.

### The demo

Command–Shift–5 on the Mac, **Record Selected Portion**, around the Mac app and the emulator side by side. One take, no talking needed; show the four steps slowly. Convert it to a GIF for the README if it is short enough, or drag the `.mp4` into the README while editing it on github.com, which uploads it and inserts the link.

### The look back

Yours, in your words. Some questions to answer, if you need a start:

- Which lesson did you have to repeat, and what made it finally make sense?
- Which bug took longest, and what did it teach you?
- Which decision in PayDeck would you defend in an interview, and which would you change?

Keep it with your notes from the start of the course. Reading them side by side is the best measure of how far you came.
