Families and small teams share money. Asha wants to give her partner Eve a card that spends from Asha's USD account, without giving Eve her password or a view of her balance. This project adds a fourth kind of person to PayDeck's rules, the **cardholder**, and it is the promise from the Module 27 project coming true: a cardholder who tries to change a limit on a card they hold gets `403`, because they are allowed to know that card exists.

## The rules

The table from lesson 30.2 gains a column:

| | owner | cardholder | support | admin |
|---|:---:|:---:|:---:|:---:|
| account: view, move money, issue card | yes | no | (as before) | (as before) |
| card: view | yes | yes | yes | yes |
| card: freeze | yes | yes | yes | yes |
| card: unfreeze | yes | **no** | yes | yes |
| card: change settings | yes | no | no | no |
| card: cancel | yes | no | no | yes |

Why may Eve freeze but not unfreeze? Freezing is the safe direction: if Eve loses the card, she should be able to stop it at once, at 2 a.m., without phoning Asha. Unfreezing turns spending back on, and the money is Asha's, so that is Asha's decision. Holding a card gives Eve no view of the account: not its balance, not its history. Paying with the card arrives in Module 32, and the cardholder will be allowed to do that too.

## The tasks

1. **The database.** `V10__add_cardholders.sql` adds `cardholder_user_id` to `cards`: a nullable reference to `users`, with an index. Empty means the owner holds the card.
2. **Issuing to someone.** `POST /api/accounts/{id}/cards` accepts an optional `cardholderEmail` (validated as an email). If it is given, find that PayDeck user and store their ID on the card; if nobody has that email, answer `422` with code `CARDHOLDER_NOT_FOUND` and the message "Nobody with that email uses PayDeck yet. Ask them to sign up first." Giving a card to yourself is the same as keeping it. Every card in a response gets `cardholderId` (or `null`).
3. **The rules.** `Relationship` gains `CARDHOLDER`, `AccessPolicy.card` recognises it, and `allows` follows the table above. Update the table in `AccessPolicy`'s comment too.
4. **"Cards given to me".** `GET /api/me` gains `heldCards`: for each card someone gave this person, the card, the owner's name, and the account's currency (the app needs it to show the limit). Not the balance.
5. **Tests.** `CardholderApiTest` with three tests: the cardholder sees the card in `/api/me` and through `GET /api/cards/{id}`, but gets `404` for the account; the cardholder may freeze, but gets `403` for unfreeze, settings and cancel, while the owner may unfreeze; and an unknown email is `422 CARDHOLDER_NOT_FOUND`. Plus one test in `AccessPolicyTest` for the cardholder column. `./mvnw test` should report 82 tests.
6. **The app.** The Issue a card screen gets an optional field, **Give it to (their PayDeck email)**. The Cards screen shows a **Given to you** section under your own cards, each with "From" and the owner's name. Opening one shows the card, a sentence explaining what you may do, and **Freeze card** if it is active, and nothing else.
7. Try the whole story with two people, and commit.

### The card

`issue` takes it as a fourth parameter and stores it:

```java
    public static Card issue(UUID accountId, String nickname, Long spendingLimitCents, UUID cardholderUserId) {
        Card card = new Card();
        card.accountId = accountId;
        card.nickname = nickname;
        card.last4 = String.format("%04d", RANDOM.nextInt(10_000));
        card.status = CardStatus.ACTIVE;
        card.spendingLimitCents = spendingLimitCents;
        card.cardholderUserId = cardholderUserId;
```

### Issuing to someone

In `CardController`, the request and the response each gain a field. `CardResponse.of` becomes `public`, because `MeController` will use it:

```java

    public record IssueCardRequest(
            @NotBlank @Size(max = 50) String nickname,
            @Positive @Max(10_000_000) Long spendingLimitCents,
            @Email String cardholderEmail) {
    }
```

```java
    public record CardResponse(
            UUID id, UUID accountId, String nickname, String last4, CardStatus status,
            Long spendingLimitCents, UUID cardholderId, Instant createdAt) {

        public static CardResponse of(Card card) {
            return new CardResponse(card.getId(), card.getAccountId(), card.getNickname(), card.getLast4(),
                    card.getStatus(), card.getSpendingLimitCents(), card.getCardholderUserId(), card.getCreatedAt());
        }
    }
```

The controller needs `UserRepository` (add it to the constructor), and `issue` looks the cardholder up:

```java
        access.account(user, accountId, AccountAction.ISSUE_CARD);
        UUID cardholder = null;
        if (request.cardholderEmail() != null && !request.cardholderEmail().isBlank()) {
            UUID found = users.findByEmail(User.normalizeEmail(request.cardholderEmail()))
                    .map(User::getId)
                    .orElseThrow(() -> new BusinessRuleException("CARDHOLDER_NOT_FOUND",
                            "Nobody with that email uses PayDeck yet. Ask them to sign up first."));
            // Giving a card to yourself is the same as keeping it.
            cardholder = found.equals(user.id()) ? null : found;
        }
        Card card = cards.save(Card.issue(accountId, request.nickname().strip(), request.spendingLimitCents(),
                cardholder));
```

New imports: `dev.paydeck.api.auth.User`, `dev.paydeck.api.auth.UserRepository`, `dev.paydeck.api.common.BusinessRuleException` and `jakarta.validation.constraints.Email`.

"Nobody with that email uses PayDeck" does tell Asha whether an email has an account. That is acceptable here: Asha has to be signed in, can only learn about one address per request, and is choosing someone she knows. Compare sign-in (lesson 27.4), where the same information would help strangers guess passwords, and is hidden.

### The rules

`Relationship.java`:

```java
public enum Relationship {
    /** They opened the account (or the card's account). */
    OWNER,
    /** The owner gave them this card. */
    CARDHOLDER,
    /** No connection at all. */
    NONE
}
```

In `AccessPolicy`, the table in the comment gets the new column:

```java
 * <pre>
 *                        owner  cardholder  support  admin
 * account: view            yes       -         yes     yes
 * account: move money      yes       -          -       -
 * account: issue card      yes       -          -       -
 * card: view               yes      yes        yes     yes
 * card: freeze             yes      yes        yes     yes
 * card: unfreeze           yes       -         yes     yes
 * card: change settings    yes       -          -       -
 * card: cancel             yes       -          -      yes
 * </pre>
```

the card rules follow it:

```java
        return switch (action) {
            case VIEW, FREEZE -> relationship != Relationship.NONE || staff;
            case UNFREEZE -> owner || staff;
            case CHANGE_SETTINGS -> owner;
            case CANCEL -> owner || role == Role.ADMIN;
        };
```

and `card` works out the new relationship:

```java
        Relationship relationship = user.id().equals(ownerId) ? Relationship.OWNER
                : user.id().equals(card.getCardholderUserId()) ? Relationship.CARDHOLDER
                : Relationship.NONE;
```

The account rules do not change at all: they only ever said yes to `OWNER`, so a cardholder is a stranger to the account. Cardholders are not recorded in the audit log, because `recordStaffAccess` only records relationship `NONE`: Eve using the card she was given is ordinary use.

### Tests

`src/test/java/dev/paydeck/api/access/CardholderApiTest.java`:

```java
package dev.paydeck.api.access;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.delete;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.patch;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import java.util.UUID;

import com.jayway.jsonpath.JsonPath;
import dev.paydeck.api.ApiTestSupport;
import org.junit.jupiter.api.Test;
import org.springframework.http.MediaType;

/** An owner gives a card to someone else, who may use it but not run it. */
class CardholderApiTest extends ApiTestSupport {

    @Test
    void theCardholderSeesTheCardButNotTheAccount() throws Exception {
        UUID ashas = openAccount("Asha", "USD");
        TestUser bea = register("Bea");
        UUID card = giveCard(ashas, bea);

        mvc.perform(get("/api/me").with(as(bea)))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.accounts.length()").value(0))
                .andExpect(jsonPath("$.heldCards[0].card.id").value(card.toString()))
                .andExpect(jsonPath("$.heldCards[0].ownerName").value("Asha"))
                .andExpect(jsonPath("$.heldCards[0].currency").value("USD"));
        mvc.perform(get("/api/cards/{id}", card).with(as(bea)))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.cardholderId").value(bea.id().toString()));
        // Holding a card is not a window into Asha's balance.
        mvc.perform(get("/api/accounts/{id}", ashas).with(as(bea))).andExpect(status().isNotFound());
    }

    @Test
    void theCardholderMayFreezeButOnlyTheOwnerUnfreezes() throws Exception {
        UUID ashas = openAccount("Asha", "USD");
        TestUser bea = register("Bea");
        UUID card = giveCard(ashas, bea);

        mvc.perform(post("/api/cards/{id}/freeze", card).with(as(bea)))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.status").value("FROZEN"));
        mvc.perform(post("/api/cards/{id}/unfreeze", card).with(as(bea)))
                .andExpect(status().isForbidden())
                .andExpect(jsonPath("$.detail").value("You are not allowed to do this to this card."));
        mvc.perform(patch("/api/cards/{id}", card).with(as(bea))
                        .contentType(MediaType.APPLICATION_JSON)
                        .content("""
                                {"spendingLimitCents": 99999}
                                """))
                .andExpect(status().isForbidden());
        mvc.perform(delete("/api/cards/{id}", card).with(as(bea))).andExpect(status().isForbidden());

        mvc.perform(post("/api/cards/{id}/unfreeze", card).with(asOwnerOf(ashas)))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.status").value("ACTIVE"));
    }

    @Test
    void someoneWhoDoesNotUsePayDeckCannotBeGivenACard() throws Exception {
        UUID ashas = openAccount("Asha", "USD");

        mvc.perform(post("/api/accounts/{id}/cards", ashas).with(asOwnerOf(ashas))
                        .contentType(MediaType.APPLICATION_JSON)
                        .content("""
                                {"nickname": "For Bea", "cardholderEmail": "nobody-%s@example.com"}
                                """.formatted(UUID.randomUUID())))
                .andExpect(status().isUnprocessableContent())
                .andExpect(jsonPath("$.code").value("CARDHOLDER_NOT_FOUND"));
    }

    private UUID giveCard(UUID accountId, TestUser cardholder) throws Exception {
        String body = mvc.perform(post("/api/accounts/{id}/cards", accountId).with(asOwnerOf(accountId))
                        .contentType(MediaType.APPLICATION_JSON)
                        .content("""
                                {"nickname": "Family card", "cardholderEmail": "%s"}
                                """.formatted(cardholder.email())))
                .andExpect(status().isCreated())
                .andReturn().getResponse().getContentAsString();
        return UUID.fromString(JsonPath.read(body, "$.id"));
    }
}
```

```ts
/** A mutation that changes a card, and then fetches your cards, and the cards given to you, again. */
function useCardMutation<Input>(change: (input: Input) => Promise<unknown>) {
  const accountId = useAccountId();
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: change,
    onSuccess: () =>
      Promise.all([
        queryClient.invalidateQueries({ queryKey: keys.cards(accountId) }),
        queryClient.invalidateQueries({ queryKey: keys.me }),
      ]),
  });
}

export function useIssueCard() {
  const accountId = useAccountId();
  return useCardMutation(
    (input: { nickname: string; spendingLimitCents: number | null; cardholderEmail: string | null }) =>
      api.issueCard(accountId, input.nickname, input.spendingLimitCents, input.cardholderEmail),
  );
}
```

## What to notice

- **One more column, one class.** A new kind of person needed changes in exactly one place, `AccessPolicy`, plus the data it reads. No controller learned anything about cardholders: they still ask "may this person freeze this card?".
- **Each relationship sees only what it needs.** The cardholder gets the card, the owner's name and the currency, and nothing about the balance or history.
- **403 and 404 mean something.** Eve gets 404 for the account (she may not know it), and 403 for unfreezing (she may know the card, but not do that).
- **The table is the specification.** It is in the comment, in the tests, and on this page, and all three say the same thing.
