**Goal:** By the end of this lesson the sign-in screen has a **Continue with Google** button. It opens the browser, Google signs the person in, and the browser hands them back to PayDeck, signed in, on the Mac and on Android. Someone new is signed up on the spot.

## Why it matters

This is where lessons 29.1 and 29.2 meet real code. Most of the OAuth machinery is already written, in Spring Security; your job is to configure it, to connect its two ends (where a sign-in starts, and what happens when Google says yes), and to make the operating system deliver the `paydeck://` link to your app.

## The idea

Here is the whole flow with PayDeck's real addresses:

1. The app makes a verifier and opens the browser at
   `http://localhost:8080/api/auth/google?redirect_uri=paydeck://auth&code_challenge=…`
2. **Your code**, `GoogleSignIn.start`, checks the `redirect_uri` and the challenge, remembers both in a short **browser session** (a cookie), and redirects to `/oauth2/authorization/google`.
3. **Spring Security** redirects to Google, with PayDeck's client ID, the scopes, `state` and `nonce`.
4. Google signs the person in and redirects back to `/login/oauth2/code/google?code=…&state=…`.
5. **Spring Security** checks `state`, trades Google's code for tokens (with the client secret), checks the ID token, and calls your success handler.
6. **Your code**, `GoogleSignIn.onSuccess`, finds or creates the PayDeck user, creates a login code with the remembered challenge (lesson 29.2), forgets the browser session, and redirects to `paydeck://auth?code=…`.
7. The operating system opens PayDeck with that link. The app posts the code and verifier to `/api/auth/token` and is signed in.

Two codes, two different jobs: Google's code (step 4) is for the API; PayDeck's login code (step 6) is for the app.

### Only send codes to the app

Step 2 checks `redirect_uri` against a list of allowed links, just `paydeck://auth`. Without that check, a phishing page could start a sign-in with `redirect_uri=https://evil.example.com` and the API would hand the code to it.

### A session, briefly

Since lesson 27.2 the API has kept no sessions: each request carries its token. Steps 2 to 6 are different: they are a series of browser visits, and the API must remember, between visits, where the sign-in started and Spring's own `state`. So the session policy changes from "never" to "only when needed" (`IF_REQUIRED`), and the success handler throws the session away as soon as it is done. API requests with tokens still never create one.

### Google is optional

A server without a Google client ID should still start, and simply say "Sign in with Google is not set up". So the Google parts are switched on only when the client ID is configured. That also keeps the tests from needing one.

## Register PayDeck with Google

You need a Google account, and the client ID and secret Google gives you. All of this is in the Google Cloud console, free, and needs no credit card.

1. Go to [console.cloud.google.com](https://console.cloud.google.com), sign in, and create a project called `PayDeck`.
2. Open **Google Auth Platform** from the menu (older guides call this part "APIs & Services → OAuth consent screen"). Google asks for some app information first: the app name `PayDeck`, your email as the support and contact address, and **External** as the audience.
3. Under **Audience**, the app starts in **Testing**: only the Google accounts you list as **test users** can sign in. Add your own Google account. That is all you need while you build; publishing is for Part 10.
4. Under **Clients**, create a client of type **Web application** (the PayDeck API is a web server, and it is the client). Add one **Authorised redirect URI**:
   ```
   http://localhost:8080/login/oauth2/code/google
   ```
   This is step 4's address: Spring Security's built-in callback. Google refuses to send anyone anywhere else, which is one more protection against stolen codes.
5. Copy the **Client ID** (ends in `.apps.googleusercontent.com`) and the **Client secret**. Treat the secret like a password.

Spring Boot reads them from two environment variables, with long but exact names. Put them in a file called `.env` in the API folder:

```sh
export SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_GOOGLE_CLIENT_ID=123456789012-abc123.apps.googleusercontent.com
export SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_GOOGLE_CLIENT_SECRET=GOCSPX-your-secret-here
```

Make sure `.gitignore` has a line `.env`, so the secret never goes into Git, and start the API with:

```sh
source .env && ./mvnw spring-boot:run
```

Spring Boot already knows everything else about Google (its addresses, and the scopes `openid`, `profile` and `email`), so these two values are all the configuration there is.

## Worked example: the API

### The library and settings

In `pom.xml`, next to the resource server starter:

```xml
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-security-oauth2-client</artifactId>
        </dependency>
```

The resource server starter (lesson 27.5) checks PayDeck's own tokens. The **client** starter is the other side: it signs in somewhere else, here Google.

In `application.yml`, under `paydeck.auth`:

```yaml
    # Where "Sign in with Google" may send people back to: the app's own link.
    app-redirect-uris: ${PAYDECK_APP_REDIRECT_URIS:paydeck://auth}
```

and `AuthProperties` gets the list:

```java
package dev.paydeck.api.auth;

import java.util.List;

import org.springframework.boot.context.properties.ConfigurationProperties;

/** The {@code paydeck.auth.*} settings from application.yml. */
@ConfigurationProperties("paydeck.auth")
public record AuthProperties(String jwtSecret, List<String> appRedirectUris) {

    public AuthProperties {
        appRedirectUris = appRedirectUris == null ? List.of() : List.copyOf(appRedirectUris);
    }
}
```

The block after the record header is a **compact constructor**: it runs when the record is created, and here turns a missing setting into an empty list. `List.copyOf` makes the list unchangeable.

### People without passwords

        user.displayName = displayName;

What happens when someone who only uses Google tries the password form? `login` reads `found.map(User::getPasswordHash)`. For them that is `null`, which `map` turns into an empty `Optional`, so the dummy hash is checked and the answer is the usual "That email and password do not match." No special case needed, and a test below proves it.

### Finding or creating the user

In `AuthService`:

```java
    /**
     * Called once Google has told us who someone is: finds them by their
     * Google ID, or signs them up. An email that already has a PayDeck
     * password is refused for now; lesson 29.4 links the two.
     */
    @Transactional
    public User signInWithGoogle(String googleSubject, String email, String name) {
        Optional<User> known = users.findByGoogleSubject(googleSubject);
        if (known.isPresent()) {
            return known.get();
        }
        String normalized = User.normalizeEmail(email);
        if (users.findByEmail(normalized).isPresent()) {
            throw new ConflictException("EMAIL_TAKEN", "Sign in with your password: this email already has an account.");
        }
        String displayName = name == null || name.isBlank() ? normalized : name;
        return users.save(User.withGoogle(normalized, displayName, googleSubject));
    }
```

People are found by `sub` first (lesson 29.1). If the email already belongs to someone who signed up with a password, this version refuses rather than guess; lesson 29.4 decides when it is safe to link them.

### The two ends of the flow

`src/main/java/dev/paydeck/api/auth/GoogleSignIn.java`:

```java
package dev.paydeck.api.auth;

import java.io.IOException;
import java.net.URI;

import dev.paydeck.api.common.ConflictException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import jakarta.servlet.http.HttpSession;
import org.springframework.beans.factory.ObjectProvider;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.http.ResponseEntity;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.AuthenticationException;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.oauth2.client.registration.ClientRegistrationRepository;
import org.springframework.security.oauth2.core.oidc.user.OidcUser;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.util.UriComponentsBuilder;

/**
 * "Sign in with Google" for an app, in four steps:
 * <ol>
 *   <li>The app makes a secret code verifier and opens the browser at
 *   {@code /api/auth/google} with its hash, the code challenge.</li>
 *   <li>The API sends the browser to Google. Spring Security handles the
 *   OAuth back-and-forth with Google.</li>
 *   <li>Google sends the browser back to the API, which finds or creates the
 *   user and sends the browser on to the app's link, {@code paydeck://auth},
 *   with a one-time code.</li>
 *   <li>The app posts the code and its verifier to {@code /api/auth/token}
 *   and gets PayDeck tokens.</li>
 * </ol>
 */
@RestController
public class GoogleSignIn {

    private static final String REDIRECT_URI = "paydeck.google.redirectUri";
    private static final String CODE_CHALLENGE = "paydeck.google.codeChallenge";

    private final ObjectProvider<ClientRegistrationRepository> googleClient;
    private final AuthService auth;
    private final AuthProperties properties;

    public GoogleSignIn(ObjectProvider<ClientRegistrationRepository> googleClient, AuthService auth,
                        AuthProperties properties) {
        this.googleClient = googleClient;
        this.auth = auth;
        this.properties = properties;
    }

    /** Step 1: remember where to send the browser back to, and the challenge, then off to Google. */
    @GetMapping("/api/auth/google")
    public ResponseEntity<?> start(@RequestParam("redirect_uri") String redirectUri,
                                   @RequestParam("code_challenge") String codeChallenge,
                                   @RequestParam(name = "code_challenge_method", defaultValue = "S256") String method,
                                   HttpServletRequest request) {
        if (googleClient.getIfAvailable() == null) {
            return problem(HttpStatus.SERVICE_UNAVAILABLE, "GOOGLE_NOT_CONFIGURED",
                    "Sign in with Google is not set up on this server.");
        }
        // Only send codes to links we know belong to the PayDeck app. Otherwise
        // a phishing page could start a sign-in and collect the code itself.
        if (!properties.appRedirectUris().contains(redirectUri)) {
            return problem(HttpStatus.BAD_REQUEST, "BAD_REDIRECT_URI", "This redirect_uri is not allowed.");
        }
        if (!"S256".equals(method) || codeChallenge.length() < 43 || codeChallenge.length() > 128) {
            return problem(HttpStatus.BAD_REQUEST, "BAD_CODE_CHALLENGE", "Send a SHA-256 (S256) code challenge.");
        }
        HttpSession session = request.getSession(true);
        session.setAttribute(REDIRECT_URI, redirectUri);
        session.setAttribute(CODE_CHALLENGE, codeChallenge);
        return ResponseEntity.status(HttpStatus.FOUND).location(URI.create("/oauth2/authorization/google")).build();
    }

    /** Step 3: Google said who this is. Send the browser back to the app with a one-time code. */
    void onSuccess(HttpServletRequest request, HttpServletResponse response, Authentication authentication)
            throws IOException {
        HttpSession session = request.getSession(false);
        String redirectUri = session == null ? null : (String) session.getAttribute(REDIRECT_URI);
        String challenge = session == null ? null : (String) session.getAttribute(CODE_CHALLENGE);
        // PayDeck uses its own tokens from here on, so forget the browser session.
        if (session != null) {
            session.invalidate();
        }
        SecurityContextHolder.clearContext();
        if (redirectUri == null || challenge == null) {
            response.sendError(HttpStatus.BAD_REQUEST.value(), "Start signing in from the PayDeck app.");
            return;
        }

        OidcUser google = (OidcUser) authentication.getPrincipal();
        try {
            User user = auth.signInWithGoogle(google.getSubject(), google.getEmail(), google.getFullName());
            String code = auth.createLoginCode(user.getId(), challenge);
            response.sendRedirect(withParam(redirectUri, "code", code));
        } catch (ConflictException e) {
            response.sendRedirect(withParam(redirectUri, "error", "account_exists"));
        }
    }

    /** Google said no, or the person pressed Cancel. */
    void onFailure(HttpServletRequest request, HttpServletResponse response, AuthenticationException e)
            throws IOException {
        HttpSession session = request.getSession(false);
        String redirectUri = session == null ? null : (String) session.getAttribute(REDIRECT_URI);
        if (redirectUri == null) {
            response.sendError(HttpStatus.UNAUTHORIZED.value(), "Google sign-in failed.");
            return;
        }
        session.invalidate();
        response.sendRedirect(withParam(redirectUri, "error", "access_denied"));
    }

    private static String withParam(String uri, String name, String value) {
        return UriComponentsBuilder.fromUriString(uri).queryParam(name, value).build().toUriString();
    }

    private static ResponseEntity<ProblemDetail> problem(HttpStatus status, String code, String detail) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(status, detail);
        problem.setTitle("Cannot sign in with Google");
        problem.setProperty("code", code);
        return ResponseEntity.status(status).body(problem);
    }
}
```

- **`ObjectProvider<ClientRegistrationRepository>`**: Spring Boot creates a `ClientRegistrationRepository` (the list of places PayDeck can sign in with) only when a client ID is configured. Asking for it through an `ObjectProvider` means "give it to me if it exists"; `getIfAvailable()` returns `null` otherwise.
- **`start`** is an ordinary endpoint. It returns `ResponseEntity<?>` because it answers either a redirect or a problem.
- **`onSuccess` and `onFailure`** are not endpoints: Spring Security calls them, as you will set up next. The `OidcUser` is the person according to Google's checked ID token: `getSubject()` is `sub`, and so on.
- **`session.invalidate()`** and **`clearContext()`**: once the login code exists, the browser session has no further use, and keeping it would leave a signed-in session lying around in the browser.
- **`UriComponentsBuilder`** adds `?code=...` correctly encoded. Gluing strings together breaks the day a value contains `&`.

### Switching it on

In `SecurityConfig`, the filter chain takes two more parameters:

```java
    @Bean
    SecurityFilterChain securityFilterChain(HttpSecurity http,
                                            ObjectProvider<ClientRegistrationRepository> googleClient,
                                            GoogleSignIn googleSignIn) throws Exception {
```

The session policy changes:

```java
                // API requests carry their own token. Only signing in with Google needs a
                // short browser session, to remember where it started.
                .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.IF_REQUIRED))
```

Spring's two Google addresses join the public ones:

```java
                        .requestMatchers("/api/auth/**", "/oauth2/**", "/login/oauth2/**").permitAll()
```

and before `return http.build();`:

```java
        // "Sign in with Google" is switched on only when a Google client ID is configured.
        if (googleClient.getIfAvailable() != null) {
            http.oauth2Login(login -> login
                    .loginPage("/api/auth/google")
                    .successHandler(googleSignIn::onSuccess)
                    .failureHandler(googleSignIn::onFailure));
        }
```

`oauth2Login` adds the two Spring addresses from the flow, `/oauth2/authorization/google` and `/login/oauth2/code/google`. `loginPage` tells it where a sign-in starts, so it does not generate its own HTML login page. `googleSignIn::onSuccess` is a method reference (lesson 17.4): "call this method when it succeeds".

## Worked example: the app

### Where the browser goes

Google accepts plain `http://` redirect addresses only for `localhost`. On the Mac that is fine. The Android emulator reaches the Mac through `10.0.2.2` (lesson 26.4), which Google would refuse. So the browser part of the sign-in always uses `localhost`, and on Android you forward it with `adb reverse`, as you would for a phone on USB. In `src/config.ts`:

```ts
/**
 * Where the browser goes to sign in with Google. Google accepts plain http://
 * only for localhost, so this is localhost on Android too, where
 * `adb reverse tcp:8080 tcp:8080` forwards it to the Mac.
 */
export const SIGN_IN_BASE_URL = 'http://localhost:8080';
```

The app's own API calls keep using `API_BASE_URL`.

### The API calls

In `src/api/auth.ts` (import `SIGN_IN_BASE_URL` from `'../config'`):

```ts
/** The app's own link. After Google, the API sends the browser here with a one-time code. */
export const APP_REDIRECT_URI = 'paydeck://auth';

/** The page that starts "Sign in with Google", opened in the browser. */
export const googleSignInUrl = (codeChallenge: string) =>
  `${SIGN_IN_BASE_URL}/api/auth/google?redirect_uri=${encodeURIComponent(APP_REDIRECT_URI)}` +
  `&code_challenge=${codeChallenge}&code_challenge_method=S256`;

/** The last step of "Sign in with Google": the one-time code and the verifier, for tokens. */
export const exchangeCode = (code: string, codeVerifier: string) =>
  request<AuthResponse>('/api/auth/token', { method: 'POST', body: { code, codeVerifier }, withToken: false });
```

`encodeURIComponent` turns `paydeck://auth` into `paydeck%3A%2F%2Fauth`, so its `:` and `/` cannot be mistaken for parts of the outer address. The challenge needs no encoding: base64url was designed for addresses.

### Reading the link

`src/auth/links.ts`:

```ts
/** The ?a=1&b=2 part of a link, as { a: '1', b: '2' }. */
export function queryParams(url: string): Record<string, string> {
  const query = url.split('?')[1] ?? '';
  const params: Record<string, string> = {};
  for (const pair of query.split('&')) {
    const [key, value = ''] = pair.split('=');
    if (key !== '') {
      params[decodeURIComponent(key)] = decodeURIComponent(value);
    }
  }
  return params;
}
```

Browsers have `URLSearchParams` for this, but React Native's version is incomplete, so a small function of your own is the reliable choice.

Above the `auth` object:

```tsx
  // After Google, the API sends the browser to paydeck://auth?code=..., the
  // system opens PayDeck with that link, and the app finishes signing in.
  async function finishGoogleSignIn(url: string) {
    const verifier = codeVerifier.current;
    if (!url.startsWith(authApi.APP_REDIRECT_URI) || verifier === null) {
      return; // Not a sign-in link, or not one this app started.
    }
    codeVerifier.current = null;
    const params = queryParams(url);
    if (params.code === undefined) {
      setGoogleError(
        params.error === 'account_exists'
          ? 'This email already has a PayDeck password. Sign in with it instead.'
          : 'Google sign-in was cancelled.',
      );
      return;
    }
    try {
      await accept(await authApi.exchangeCode(params.code, verifier));
    } catch (e) {
      setGoogleError((e as Error).message);
    }
  }

  // Listen for links. Like the token source, this always uses this render's function.
  useEffect(() => {
    const subscription = Linking.addEventListener('url', ({ url }) => finishGoogleSignIn(url));
    return () => subscription.remove();
  });
```

and in the `auth` object:

```tsx

      setGoogleError(null);
      codeVerifier.current = newCodeVerifier();
      await Linking.openURL(authApi.googleSignInUrl(codeChallenge(codeVerifier.current)));
    },
    googleError,
```

- **`Linking.openURL`** opens an address in the default browser. **`Linking.addEventListener('url', ...)`** is called when the system opens the running app with a link.
- **Ignoring links without a verifier**: a `paydeck://auth` link the app did not ask for (an old one, or one someone sent) does nothing.
- **`codeVerifier.current = null`** before anything else: a verifier is used once, whatever happens next.
- **`accept`** is the same function password sign-in uses (lesson 28.4): it saves the refresh token and switches to `signedIn`. Everything after this point is identical.
- **The effect** has no dependency list and does clean up: it removes the old listener and adds a new one after every render, so the listener always calls the current `finishGoogleSignIn`. Removing and adding happen in one go, so no link can slip through between them.

### Telling the system that `paydeck://` links are PayDeck's

**Android.** In `android/app/src/main/AndroidManifest.xml`, inside the `<activity android:name=".MainActivity" ...>` element, next to the existing `<intent-filter>`, add a second one:

```xml
        <!-- Opens the app for paydeck://auth links (after "Sign in with Google"). -->
        <intent-filter>
            <action android:name="android.intent.action.VIEW" />
            <category android:name="android.intent.category.DEFAULT" />
            <category android:name="android.intent.category.BROWSABLE" />
            <data android:scheme="paydeck" android:host="auth" />
        </intent-filter>
```

`VIEW` plus `BROWSABLE` means "a browser may open me for links like this". The activity already has `android:launchMode="singleTask"` from the template, so the link arrives in the running app instead of starting a second copy.

**macOS.** Two steps. First, `macos/PayDeck-macOS/Info.plist` declares the scheme. Add inside the top-level `<dict>`:

```xml
	<key>CFBundleURLTypes</key>
	<array>
		<dict>
			<key>CFBundleURLName</key>
			<string>PayDeck sign-in</string>
			<key>CFBundleURLSchemes</key>
			<array>
				<string>paydeck</string>
			</array>
		</dict>
	</array>
```

Second, macOS gives the link to the app's delegate, which must pass it on to React Native. In `macos/PayDeck-macOS/AppDelegate.swift`, add this method inside `class AppDelegate`:

```swift
  // macOS calls this when a paydeck:// link is opened, for example when the
  // browser comes back from "Sign in with Google". Passing it on as this
  // notification makes it arrive in JavaScript through Linking's "url" event.
  func application(_ application: NSApplication, open urls: [URL]) {
    for url in urls {
      NotificationCenter.default.post(
        name: NSNotification.Name("RCTOpenURLNotification"),
        object: self,
        userInfo: ["url": url.absoluteString]
      )
    }
  }
```

React Native's `Linking` module on macOS listens for exactly this notification, `RCTOpenURLNotification`, with the link in `userInfo["url"]`.

Native files changed, so rebuild both apps.

### Try it

On the Mac, start the API with `source .env && ./mvnw spring-boot:run`, run the app, and tap **Continue with Google**.

1. Your browser opens on Google's sign-in page. Choose the Google account you added as a test user. If Google shows a warning that the app is still in testing, continue.
2. Google asks whether PayDeck may see your name, email and profile picture. Continue.
3. The browser goes to `localhost:8080`, then to `paydeck://auth?code=...`, and asks whether to open PayDeck. Allow it.
4. PayDeck comes to the front: **Welcome to PayDeck**, with your Google name. You are new, so you open an account as usual.

Quit and reopen: you are still signed in, through the refresh token, exactly as with a password. Sign out, tap **Continue with Google** again: this time Google may skip the questions and you are back in your wallet at once.

On Android, run `adb reverse tcp:8080 tcp:8080` first, then the same. The emulator's browser needs to be signed in to (or sign in to) a Google test user.

Try **Cancel** on Google's page: PayDeck says "Google sign-in was cancelled." Try the Google account whose email you used for a password account, if you have one: "This email already has a PayDeck password. Sign in with it instead."

## Common mistakes

<Aside type="caution" title="redirect_uri_mismatch">
Google's error page says this when the callback address is not exactly one of the client's **Authorised redirect URIs**: `http` not `https`, `localhost` not `127.0.0.1`, port `8080`, path `/login/oauth2/code/google`. On Android it means the browser reached the API as `10.0.2.2`; use `localhost` with `adb reverse`.
</Aside>

<Aside type="caution" title="The browser opens, but the app never hears back">
On the Mac, check the `Info.plist` entry and the `AppDelegate` method, and rebuild: a reload does not pick up either. On Android, check that the intent filter is inside the `MainActivity` element.
</Aside>

<Aside type="caution" title="Committing .env">
The client secret lets anyone pretend to be PayDeck to Google. If it was ever pushed, create a new secret in the Google console and delete the old one: a secret in Git history stays there.
</Aside>

## Recap

- Google needs a **Web application** client with the redirect URI `http://localhost:8080/login/oauth2/code/google`; its ID and secret go in `.env`, never in Git.
- `/api/auth/google` checks the app's link and challenge, keeps them in a short session, and hands over to Spring's `oauth2Login`.
- The success handler finds or creates the user, makes a login code, ends the session, and redirects to `paydeck://auth?code=...`.
- The app opens the browser with `Linking.openURL`, catches the link with `Linking.addEventListener('url')`, and trades the code and verifier for tokens.
- Android needs an intent filter; macOS needs `CFBundleURLTypes` and an `AppDelegate` method.
