**Goal:** By the end of this lesson you have the full PayDeck code on your Mac, and you know where each part lives.

## Why it matters

You will build PayDeck yourself, step by step. But it helps enormously to have the finished version next to you: to compare when you are stuck, and to see where you are heading. Downloading a repository from GitHub is called **cloning**, and it is how you will start working on any existing project, at any job.

## The idea

`git clone` downloads a repository **with its whole history**, and sets up `origin` to point back at it. It is not just a copy of the files: you can see every commit ever made, and pull updates later.

## Worked example

```sh
cd ~/Projects
git clone https://github.com/bludbud-cmd/fullstack-payments-course.git
cd fullstack-payments-course
ls
```

You will see:

| Folder | What it is | Built in |
| --- | --- | --- |
| `api` | The PayDeck server: Java 25 and Spring Boot | Parts 4 to 6, 8 and 9 |
| `app` | The PayDeck app: React Native for Android and macOS | Parts 3 and 7 to 9 |
| `site` | This website | (You are reading it) |
| `.github` | Automated checks that run on every change | Part 10 |

Look around:

```sh
git log --oneline | head -20
```

`| head -20` sends the output of `git log` into `head`, which shows only the first 20 lines. Each line is a step in building PayDeck. Many say "Merge pull request #…": each feature was built on a branch and merged, just like lesson 3.2.

```sh
code .
```

Opens the whole project in VS Code (`.` means "this folder"). Open `app/README.md` and `api/README.md`: each explains its half of PayDeck. Do not worry about understanding the code yet; by the end of the course you will.

### Keeping it up to date

The course code may get fixes and improvements. To get them:

```sh
cd ~/Projects/fullstack-payments-course
git pull
```

<Aside type="caution" title="Build your own, read this one">
Build your PayDeck in your own folder and repository, and use this clone only to read and compare. If you edit the clone, `git pull` may hit conflicts with the course's own changes.
</Aside>

## Recap

- `git clone URL` downloads a repository with its entire history.
- The course repository has `api` (server), `app` (client) and `site` (this website).
- `git pull` brings in updates later.
- Build your own PayDeck separately; use the clone to read and compare.
